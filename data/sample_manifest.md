# Sample data manifest - Pune CAAQMS weeks 1 & 2

Generated by `scripts/make_sample_data.py` (seed 20261101, deterministic; re-running reproduces the files byte-for-byte).
Regenerate with: `.venv/bin/python scripts/make_sample_data.py`

## Row id convention

- `R<n>` = 1-based index of the data row **after the header row**, in file order.
- `sample_week1.csv` has a 2-line title/subtitle ABOVE the header; those lines are not data rows and do not consume R ids. `sample_week2.csv` has no title lines.
- Row order: day -> station (alphabetical: Bhosari, Hadapsar, Karve Road, Katraj, Nigdi, Pashan, Shivajinagar, Swargate) -> hour 00-23.
- Outage hours are ABSENT rows (no R id exists for them). The duplicate row shifts every later R id by +1; **all ids below are the final file ids**, verified by re-reading the written files with pandas.

## Files and layout

| file | data rows | period | layout |
|---|---|---|---|
| data/sample_week1.csv | 567 | 2026-11-01..03, hourly | wide (1 row = station-hour); 2 title/subtitle lines above the header |
| data/sample_week2.csv | 547 | 2026-11-08..10, hourly | wide (1 row = station-hour); no title lines |

Counts: week1 567 = 8x72 - 10 (Pashan outage rows) + 1 (duplicate); week2 547 = 8x72 - 10 (Nigdi day-1 outage) - 20 (Nigdi day-3 rows absent) + 1 (duplicate).

Columns (both files, in order): station, ward, date, time, PM2.5, PM10, NO2, SO2, O3, CO. Headers are deliberately inconsistent between (and within) files; units in headers are unreliable by design - cell-embedded units are authoritative.

- PM10 ~ 1.85-2.10 x PM2.5; NO2/SO2/O3/CO follow traffic/industrial/photochemical shapes (O3 peaks 12:00-16:00, PM peaks 07:00-09:00 and 18:00-22:00).
- Expected daily AQI span: week1 Moderately Polluted..Very Poor (Hadapsar 03 Nov ~ Very Poor); week2 adds Satisfactory at Karve Road/Pashan and Very Poor at the two hotspots. Daily means land within ~±5% of the targets.
- Units: standard is µg/m3 for all pollutants except CO (mg/m3). Shivajinagar reports NO2/O3 in ppb (cells stamped 'ppb'); Katraj reports CO in µg/m3 (cells stamped 'µg/m3' with thousands separators). All other cells are plain numbers in the standard unit, so they carry the documented UNIT_AMBIGUOUS caveat under the 'missing unit -> assume standard' rule.

## Notes for test authors

| Planted cell | Expected flag / behaviour |
|---|---|
| `NA`, `N/A`, `--`, `-`, `NULL`, `ND`, `-999`, `9999` | SENTINEL (value unusable) |
| blank cell | MISSING |
| `-12.5` (PM10), `-3.2 ppb` (O3) | NEGATIVE, value NaN |
| `2750` (PM2.5), `3100` (PM10), `1180` (O3) | OUT_OF_RANGE, value NaN |
| `<5` | CENSORED |
| 9-12 identical consecutive readings | STUCK (values stay usable) |
| duplicate row copy | DUPLICATE on the later copy |
| `22.6 ppb` (Shivajinagar NO2/O3) | UNIT_CONVERTED (x1.88 / x1.96) |
| `1,836 µg/m3` (Katraj CO) | UNIT_CONVERTED (/1000) + thousands separator |
| Pashan 2026-11-02 | PARTIAL_DAY: only 14 valid hours -> no valid daily AQI |
| Nigdi week2 | LOW_COVERAGE / unreliable (coverage ~0.49; day 1 AQI valid but built on a stuck PM2.5, days 2-3 invalid) |

- All dates have day <= 12, so DD/MM vs MM/DD is genuinely ambiguous; the contract rule (assume DD/MM) yields the correct dates.
- The duplicate rows are byte-identical copies (station, ward, date, time and every cell); detection is by repeated station+timestamp, not by value drift.
- The manifest is regenerated by the same script run that wrote the CSVs, so the ids here always match the files.
